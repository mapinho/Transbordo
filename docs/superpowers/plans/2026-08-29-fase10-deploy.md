# Fase 10 — Deploy — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the Django stack (Fases 5–9) into production alongside Streamlit: gunicorn + a Procrastinate `worker` in Docker, behind Apache on a new subdomain, with `/healthz/` doing a real `SELECT 1` and a manual deploy runbook.

**Architecture:** One Docker image (bumped to `python:3.13-slim`, `gunicorn` + `whitenoise` added, `collectstatic` in the build). Three new `docker-compose.yml` services from that image — `web` (gunicorn), `worker` (Procrastinate), `migrate` (one-off, `profiles: [tools]`). Apache reverse-proxies `transbordo.vectorconsulting.com.br` → `127.0.0.1:8000`. The Streamlit `comigo` service and `comigo*.conf` stay untouched (Fase 11 removes them); the `mcp` SSE service is deleted now (nothing uses it after Fase 9a).

**Tech Stack:** Docker + docker compose, gunicorn, WhiteNoise, Apache (`mod_proxy` + `mod_ssl`), Django 6, `pytest`/`pytest-django`, PostgreSQL (external, bare-metal on the host).

**Spec:** `docs/superpowers/specs/2026-08-29-fase10-deploy-design.md`

## Global Constraints

- **Do NOT touch the Streamlit stack:** `app.py`, `app_logic.py`, `models.py`, `calculations.py`, `scenarios.py`, `data_loader.py`, `logistics_services.py`, `utils.py`, `ai_assistant.py`, `mcp_server.py`, `tests/` (SQLAlchemy), `comigo.conf`, `comigo-le-ssl.conf`. Their removal is Fase 11.
- **Migrations stay manual** — no `migrate` in any Docker entrypoint or `CMD`. The `migrate` compose service is `profiles: ["tools"]` and only runs when invoked explicitly.
- New dependencies pinned in `requirements.txt`: `gunicorn>=23,<24`, `whitenoise>=6.6,<7`.
- `Dockerfile` base image: `python:3.13-slim` (Django 6 needs ≥3.12; project developed against 3.13).
- Subdomain: `transbordo.vectorconsulting.com.br`. `web` binds `127.0.0.1:8000` (loopback only — Apache is the only ingress).
- `DJANGO_SETTINGS_MODULE=config.settings.prod` is set in each Django service's compose `environment:` block, **never** in the shared `.env`.
- Container → host PostgreSQL via `extra_hosts: ["host.docker.internal:host-gateway"]` + `DJANGO_DB_HOST=host.docker.internal`.
- `python manage.py check --deploy` under `config.settings.prod` must report **0 issues** (a strong `DJANGO_SECRET_KEY` is assumed present).
- TDD only where there is Python logic (Task 1). Infra tasks (2–6) are verified by build/check/compose commands, spelled out per task.
- Django tests run under `config.settings.dev` (`pytest.ini`) — WhiteNoise's manifest storage must live in `prod.py` only, so it never breaks the test suite.
- Commit style: `feat(deploy):` / `feat(core):` / `chore(deploy):` / `docs:`, pt-BR summary. End every commit message with:

```python
from django.conf import settings
from django.db import connection
from django.db.utils import OperationalError
from django.http import JsonResponse


def healthz(request):
    """Health check: versão da aplicação + SELECT 1 no banco. Sem auth.
    Usado pelo HEALTHCHECK do container `web` e pelo poll do deploy.sh."""
    try:
        with connection.cursor() as cursor:
            cursor.execute('SELECT 1')
            cursor.fetchone()
        db_ok = True
    except OperationalError:
        db_ok = False
    return JsonResponse(
        {'version': settings.APP_VERSION, 'db': 'ok' if db_ok else 'erro'},
        status=200 if db_ok else 503,
    )
```

```python
from .base import *  # noqa: F401,F403

DEBUG = False

# TLS termina no Apache (proxy reverso) na frente da aplicação — o Django nunca
# fala HTTPS diretamente. Sem SECURE_PROXY_SSL_HEADER, request.is_secure()
# sempre volta False atrás do proxy.
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')

SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True

SECURE_HSTS_SECONDS = 31536000
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True

CSRF_TRUSTED_ORIGINS = [f'https://{host}' for host in ALLOWED_HOSTS if host]  # noqa: F405

# gunicorn serve os estáticos (comprimidos, hasheados) via WhiteNoise — sem
# Alias no Apache, sem volume. `collectstatic` roda no build do Docker.
MIDDLEWARE = (  # noqa: F405
    MIDDLEWARE[:1]  # noqa: F405
    + ['whitenoise.middleware.WhiteNoiseMiddleware']
    + MIDDLEWARE[1:]  # noqa: F405
)
STORAGES = {  # noqa: F405
    'default': {'BACKEND': 'django.core.files.storage.FileSystemStorage'},
    'staticfiles': {'BACKEND': 'whitenoise.storage.CompressedManifestStaticFilesStorage'},
}

import os  # noqa: E402

if os.getenv('DJANGO_EMAIL_HOST'):
    EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'  # noqa: F405
    EMAIL_HOST = os.getenv('DJANGO_EMAIL_HOST')
    EMAIL_PORT = int(os.getenv('DJANGO_EMAIL_PORT', '587'))
    EMAIL_HOST_USER = os.getenv('DJANGO_EMAIL_HOST_USER', '')
    EMAIL_HOST_PASSWORD = os.getenv('DJANGO_EMAIL_HOST_PASSWORD', '')
    EMAIL_USE_TLS = os.getenv('DJANGO_EMAIL_USE_TLS', 'true').lower() == 'true'
```

## Task 5: Apache vhosts for the subdomain

- [ ] **Step 1: Create `transbordo.conf`**

```apache
    ServerAdmin mapinho@vectorpg.com.br
    ServerName transbordo.vectorconsulting.com.br

    RewriteEngine on
    RewriteCond %{SERVER_NAME} =transbordo.vectorconsulting.com.br
    RewriteRule ^ https://%{SERVER_NAME}%{REQUEST_URI} [END,NE,R=permanent]

    ErrorLog ${APACHE_LOG_DIR}/transbordo-error.log

</VirtualHost>
```

- [ ] **Step 2: Create `transbordo-le-ssl.conf`**

```apache
<IfModule mod_ssl.c>
<VirtualHost *:443>
    ServerAdmin mapinho@vectorpg.com.br
    ServerName transbordo.vectorconsulting.com.br

    <Proxy *>
        Require all granted
    </Proxy>

    ProxyPreserveHost On
    RequestHeader set X-Forwarded-Proto "https"

    ProxyPass / http://127.0.0.1:8000/
    ProxyPassReverse / http://127.0.0.1:8000/

    ErrorLog ${APACHE_LOG_DIR}/transbordo-error.log
    CustomLog ${APACHE_LOG_DIR}/transbordo-access.log combined

    SSLCertificateFile /etc/letsencrypt/live/transbordo.vectorconsulting.com.br/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/transbordo.vectorconsulting.com.br/privkey.pem
    Include /etc/letsencrypt/options-ssl-apache.conf
</VirtualHost>
</IfModule>
```

```bash
#!/bin/bash
# Deploy recorrente do stack Transbordo (Django) em /opt/comigo.
# Primeira vez / DNS / certbot / Apache: ver docs/DEPLOY.md.
set -euo pipefail
cd /opt/comigo

echo "--- git pull ---"
git pull origin main

echo "--- build (web, worker) ---"
docker compose build web worker

echo "--- migrate (explícito) ---"
docker compose run --rm migrate

echo "--- check --deploy ---"
docker compose run --rm web python manage.py check --deploy

echo "--- up -d (web, worker) ---"
docker compose up -d web worker

echo "--- poll /healthz/ ---"
for i in $(seq 1 20); do
  if curl -fsS http://127.0.0.1:8000/healthz/ | grep -q '"db": *"ok"'; then
    echo "healthz OK"
    docker compose ps
    exit 0
  fi
  sleep 3
done
echo "ERRO: /healthz/ não respondeu db:ok em 60s" >&2
docker compose logs --tail=50 web >&2
exit 1

# --- legado (Streamlit) — Fase 11 remove ---
# O serviço `comigo` continua no docker-compose.yml e é reiniciado à parte:
#   docker compose up -d --build comigo
```

   ```
3. **PostgreSQL** — o container conecta pela rede bridge do Docker. No host:
   - `postgresql.conf`: `listen_addresses = '*'` (ou o IP da bridge `docker0`, tipicamente `172.17.0.1`).
   - `pg_hba.conf`: `host  transbordo  transbordo  172.16.0.0/12  scram-sha-256`.
   - `systemctl reload postgresql`.
   - Criar o banco/role se ainda não existir (ver `docs/decisions/0002-...`).
4. **Certificado** — `sudo certbot --apache -d transbordo.vectorconsulting.com.br`.
   (Isso cria `transbordo-le-ssl.conf` automaticamente; se o certbot gerar um arquivo próprio,
   substitua-o pelo `transbordo-le-ssl.conf` deste repo, mantendo as linhas `SSLCertificate*`.)
5. **Apache** — `sudo cp transbordo.conf transbordo-le-ssl.conf /etc/apache2/sites-available/` →
   `sudo a2ensite transbordo transbordo-le-ssl` → `sudo apache2ctl configtest` → `sudo systemctl reload apache2`.
6. **Primeira migração** — `docker compose run --rm migrate`.
7. **Admin Vector** — `docker compose run --rm web python manage.py criar_admin_vector <user> --email <email>`.
8. **Subir** — `docker compose up -d web worker` e conferir `docker compose ps` (web = healthy).
```
